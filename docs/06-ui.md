# 06 — UI 設計

## 1. フレームワークとクローム

- WPF on .NET 10 + **WPF-UI 4.3.0**(`FluentWindow`、`WindowBackdropType.Mica`、ダークモード、
  Win11 SnapLayouts 対応 TitleBar、タブはタイトルバー内)。
- .NET 組み込みの Fluent テーマは使わない(まだ `[Experimental("WPF0001")]`)。
- WPF-UI のコントロールは**薄いアプリ内抽象でラップ**する(単一ベンダー依存のリスク緩和。4.3.0 ピン)。
- テーマはシステム追従(ライト/ダーク)。Mica は 4K/125% DPI で目視検証。

## 2. 仮想化規約(絶対規則 — 違反すると静かに死ぬ)

### 詳細ビュー

ネイティブ `ListView` + `GridView` に必須設定:

```xml
VirtualizingPanel.VirtualizationMode="Recycling"
VirtualizingPanel.ScrollUnit="Pixel"
VirtualizingPanel.CacheLength="1,1"
ScrollViewer.CanContentScroll="True"   <!-- False にすると仮想化が黙って無効化される。WPF 性能バグ第1位 -->
```

- 行テンプレートはフラットな単一 Grid。I/O するコンバーター禁止。
- .NET 10 は dotnet/wpf#9181(UIA 下で行ごと O(n) IndexOf)の修正を含むが、
  それでも **Narrator + MS-IME を接続した状態でのストレステスト**を M1/M17 で実施。
  プロファイルが要求したらスリム化カスタム AutomationPeer を出す(準備済みフォールバック)。

### アイコン/サムネイルグリッド

VirtualizingWrapPanel 2.5.2(リサイクル、グループ化、可変サイズ対応)。
ピクセルパーフェクトなグループヘッダーが必要になるまでカスタム VirtualizingPanel は書かない。

### ソート/グループ化

- ビューモデルは素の配列。`Array.Sort` + StrCmpLogicalW コンパレーター → コレクション差し替え + Reset。
- **`SortDescriptions` 禁止**(実測: 200k 行で 3 分 vs 2 秒)。
- **CollectionView グループ化禁止**(実測: MeasureOverride 2471 ms vs 79 ms)。
  グループ化 = 平坦リスト + 合成ヘッダー行。
- 選択保持・先行入力選択・差分マージ(行の挿入/削除/リネームを選択を壊さず適用)は VM に手実装。
  LLM が微妙に間違えやすい箇所なので M14 のキーボードパリティチェックリストに明示的な受け入れテストがある。

## 3. タブ / ペイン

- カスタムタブストリップ(ネイティブ TabControl の restyle ベース)+ **永続タブコンテンツ**:
  WPF TabControl は ItemsSource 使用時にタブ切替でビジュアルツリーを破棄する →
  「常時インスタンス化ビュー + Visibility 切替」パターンを使う。
- ドラッグ並べ替えは v1(~200 LOC の ItemsPanel 作業)。ティアオフは post-v1
  (Dragablz は 2024 年から停滞 — 依存しない)。
- デュアルペイン = Grid + GridSplitter(M14)。
- タブ切替 < 50 ms(10 タブ × 10万件フォルダーで検証)。

## 4. アドレスバー

複合コントロール: WPF-UI `BreadcrumbBar`(表示)⇔ `AutoSuggestBox`(編集)をクリック/Ctrl+L/Alt+D/F4 で切替。
Explorer と同一挙動 + 補完はインメモリのファイル名インデックス給電(Explorer には出せない瞬間パス補完)。
環境変数展開、引用符付きパス貼り付け、UNC 入力。

## 5. 検索 UX

- タイトルバー内検索ボックス。結果は同じ仮想化 ListView にストリーム表示。
- Everything 文法フィルター、Ctrl+P グローバルジャンプパレット、Ctrl+Shift+E 最近の場所パレット。
- デバウンスなし(docs/03 §4)。結果行は一級のファイル行(右クリック・D&D・F2 全部動く)。

## 6. 起動戦略(「即時」の正体)

- **既定で常駐**(トレイアイコン、設定でオフ可)— アプリ自身がインデックス保持者なので常駐は
  アーキテクチャ上も必要。ウィンドウ表示は事前生成の隠しウィンドウで **< 100 ms 体感**
  (Everything / PowerToys Run と同じパターン)。
- コールドスタート: R2R + `ProfileOptimization`(MultiCore JIT)+ App.xaml の辞書最小化 +
  シェル以外のサービス初期化を初回描画後へ遅延 → ウォーム 200–500 ms、コールド最悪 1–2 s。
  常駐パスが保証であることを正直に文書化。
- クラッシュ復元: セッション(タブ/パス)5 秒ごと永続化 + `RegisterApplicationRestart`。

## 7. 日本語 / IME(選定理由そのもの)

- すべてのテキスト入力サーフェス — インプレースリネーム TextBox、アドレスバーの AutoSuggestBox 切替、
  検索ボックス — は、そのサーフェスが生えたマイルストーンで実機 Windows 11 + MS-IME テスト
  (インライン変換、候補ウィンドウ位置、Tab での変換サイクル)。
- ファイル名は UTF-16 end-to-end。UTF-8 経由の損失変換禁止。
- NFC/NFD・全角・サロゲートペアのフィクスチャは CI 常備(mkfixture が生成)。
- 検索折りたたみは検索コピーのみ(元名は不変)。
- UI 文字列は .resx、ja-JP 既定。
